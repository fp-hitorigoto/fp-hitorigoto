## プロジェクト概要

### ブログ「FPのひとりごと」
- URL：https://fp-hitorigoto.github.io/fp-hitorigoto/
- 技術：Astro（静的サイト）/ GitHub Pages 自動デプロイ

- 記事ファイル場所：`src/content/articles/`

### note
- URL：https://note.com/fp_hitorigoto
- ターゲット：一般の生活者・実生活でお金の悩みを持つ人（FP受験者にも参考になる内容）

### X
- ブログへの誘導投稿。**文面は「ブログで詳しく解説しています」、末尾は「詳しくはブログで👇」＋その日のブログ個別記事URL**（`https://fp-hitorigoto.github.io/fp-hitorigoto/articles/<記事ファイル名(.md除く)>/`）
- 「noteにまとめました」とは書かない（リンク先がブログなので文面と不一致になるため。2026-10-08に是正）
- 文字数は実際に投稿できた基準（全角2・URL23字換算で約237〜239）に揃える。短めに作る

## 現在の運用フロー（2026-07時点・確立済み）

### 毎朝の自動処理（GitHub Actions）
1. **毎朝自動記事生成**（`daily_update.yml`／`scripts/fetch_and_generate.py`・7:00 JST）
   - 官公庁RSS → キーワードフィルタ → Haiku選定 → **Haiku**で記事生成 → 自動push
   - 実際はほとんど生成されない（フィルタが厳しい・正常動作）
2. **毎朝トレンド記事生成**（`trends_update.yml`／`scripts/fetch_trends_and_generate.py`・8:00 JST）
   - Google Trends・NHK・Yahoo!ニュース → Haikuで記事化判定 → **Sonnet**でブログ記事生成 → **同時にnote下書きも生成**（`docs/note_*.md`）→ 自動push
3. push後、**GitHub Pagesが自動デプロイ**（両ワークフローの完了をトリガーに起動する設定済み）

### しゅうぞうさんとClaudeの分担（記事生成後）
しゅうぞうさんが「noteの下書きありますか」と聞く →

| 媒体 | Claudeがすること | しゅうぞうさんがすること |
|------|----------------|----------------------|
| ブログ | 生成済み記事の内容チェック（カテゴリ・FP試験ポイント・事実確認） | 確認するだけ |
| note | 下書きを読み、**本文・タイトル案・ハッシュタグ・X投稿文・カバー画像を1ターンでまとめて提示**（カバー画像は了承を待たず同時に作る。2026-10-22指示） | コピペして投稿 |
| X | 投稿文作成（ブログ個別記事URL・文字数は基準に揃える） | コピペして投稿 |

- 投稿完了の報告を受けたら、そのカバー画像を `~/Downloads/note_covers_archive/` に移動する（Downloads直下を散らかさない）
- 毎回、新しい記事ファイルは**事実確認**（WebSearch/WebFetchで一次情報と照合）してから投稿へ進む。誤りがあれば blog と note 両方を直し、ビルド確認→ユーザー承認→push
- noteカバー画像：Pillowで1280×670px・ネイビー(18,38,71)×ゴールド(212,175,55)・左にタイトル/右に数字や要点・下部にゴールド帯・保存先 `~/Downloads/note_○○_cover.png`
- 複雑なイラスト（手・人物・買い物カゴ等）はNG。文字＋シンプルな図形・数字で構成する

## 記事チェックで見るポイント（過去に実際にあった問題）

1. **事実に基づかない記述**：「FP試験でも近年出題」等の根拠不明な断定（07-05にプロスペクト理論記事で発生→修正済み）。怪しい記述はWebSearchで裏取りする
2. **カテゴリの誤り**：内容と合わないカテゴリ（高額療養費が「NISA・iDeCo」になっていた例）。カテゴリはconfig.tsの8種類のみ・新規追加禁止
3. **同一ニュースの重複記事**：別ソース・別タイトルですり抜けることがあった（税収84兆円・日銀短観・確定拠出年金で発生→いずれか削除で対応済み）
4. **不自然な日本語**：「月1級を受給」のような機械的表現
5. **RSS見出しそのままのタイトル**：官庁発表の転載っぽい記事は要注意
6. **制度の「仕組み」の説明が誤っている**：10/18の食料品消費減税の記事で、農家の減収理由を「受け取る消費税は減るのに払う消費税はそのまま」と説明していたが誤り。一般課税なら仕入税額控除で還付されるため損はせず、減収の中心は**売上1,000万円以下の免税事業者**だった。数値だけでなく**制度ロジックそのもの**を裏取りすること
7. **報道ごとに数字が違う**：同じ給付金でも日経「約5%」・共同通信「税抜売上高の5.4%」と差がある。片方だけ断定せず、出典を添えて併記する
8. **記事内の「◯◯年時点」のズレ**：10/18の記事は2026年の報道なのに「2025年時点での検討段階」と書かれていた。年号チェックの自動コメントが付かないケースもあるので目視で確認する
9. **自動チェック（Haiku）が正しい情報を消すことがある**：10/22のオンチェーン金融記事で、実際は2026年10月20日（2日前）の出来事なのに、生成時の年号表記が「2025年」と誤っていたため、Haikuが「過去の出来事」と判断して日付を「（時期は要確認です）」に置き換えていた。**⚠️コメント付きの記事は、記述を信用せず必ず一次情報（官公庁サイト）で日付と事実を確認し、正しい情報を復元する**
10. **判定基準の「かつ／または」と計算例**：10/20の下書きで「年金160万＋利子30万で200万円に届く」という誤りがあった（160+30=190で届かない。さらに後期高齢者医療の2割負担は「課税所得28万円以上」**かつ**「年金収入＋その他の合計所得金額200万円以上」の**両方**が必要）。数値例は必ず自分で計算し直し、複数条件は「かつ」か「または」かを確認する

### 手動作成記事の運用（2026-10-20に初実施）

自動生成に頼らず、しゅうぞうさんが別のチャットで作った下書きをもとに記事化するパターンが発生。手順は以下。

1. しゅうぞうさんが下書きファイル（例：`~/Downloads/kouki-kinyushotoku-draft.md`）を渡す
2. Claudeが**一次資料（官公庁PDF等）まで遡って事実確認**する。`pdftotext -layout` でPDFを本文抽出できる
3. ブログの型に再構成：結論ファースト → 解説 → FP試験のポイント → 実生活への影響・活用法 → まとめ
4. 下書きの絵文字見出し（💡📝）は削除、**記事本文のURL・内部リンクは全削除**（スタイルガイドのNG事項）、出典は機関名・資料名・日付のテキストで記載
5. 「お客さま」など勤務先が推測される表現は言い換える
6. note版を `docs/note_YYYY-MM-DD_slug.md` に作成 → ビルド確認 → 承認後push

※手動記事も `src/content/articles/` に置けば、翌日以降のトレンド生成で重複判定の対象になる（二重投稿の心配なし）

## 記事スタイルガイドライン

### ブログ記事
- **文体**：「ですね・ですよね」を自然な流れで使う。寄り添うトーン
- **構成**：結論ファースト → 理由・背景 → FP試験のポイント（出題範囲内の場合）→ 実生活への影響・活用法 → まとめ
- **必須**：事実ベース。不確かな情報は「〜とされています」「要確認」と明記

### note記事
- **文体**：同じ調子でより語りかける感じ。「もしあなたが〜だったら」「実際に相談を受けることがあります」
- **内容**：実生活への応用中心。FP試験セクションは入れない
- **分量**：1200〜1800字程度

### 共通NG
- 根拠のない断定（特に金融・制度情報）
- 所属組織が特定できる表現（「金融機関の現場では」のような一般表現に）
- 記事本文へのURL・リンク記載
